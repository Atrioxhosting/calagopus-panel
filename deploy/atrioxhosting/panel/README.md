# Atrioxhosting Calagopus Panel deployment

This directory captures the non-secret, host-specific state required to rebuild
the standalone Calagopus Panel deployment on the prepared Atrioxhosting Panel VM.
The complete execution requirements are in
[`../calagopus-specification.md`](../calagopus-specification.md) and remain the
authoritative source of truth.

## Captured VM-only state

| Active VM path or setting | Repository source | Purpose |
| --- | --- | --- |
| `/opt/calagopus-panel/compose.yml` | `compose.yml` | Standalone Panel stack, absolute persistence, loopback backend and dual-stack bridge |
| `/usr/local/lsws/conf/httpd_config.conf` | `openlitespeed/httpd_config.conf` | 16-worker OpenLiteSpeed server and IPv6-only HTTPS Panel origin listener |
| `/usr/local/lsws/conf/vhosts/calagopus-panel/vhconf.conf` | `openlitespeed/vhconf.conf` | Reverse proxy to `127.0.0.1:8000` |
| `/usr/local/lsws/admin/conf/admin_config.conf` | `openlitespeed/admin_config.conf` | WebAdmin restricted to `127.0.0.1:7080` |
| `/etc/nftables.d/calagopus-nat66.nft` | `nat66/calagopus-nat66.nft` | Dedicated NAT66 table for the Docker ULA subnet |
| `/usr/local/sbin/calagopus-nat66-load` | `nat66/calagopus-nat66-load` | Idempotent NAT66 loader |
| `/etc/systemd/system/calagopus-nat66.service` | `systemd/calagopus-nat66.service` | Persistent NAT66 lifecycle |
| Runtime directory modes and TLS placement | `install-panel.sh` | Reproducible installation under `/opt/calagopus-panel` |

The working VM was validated with Debian 13, Docker Engine 29.8.1, Docker
Compose 5.5.1 and OpenLiteSpeed 1.9.2. `install-prerequisites.sh` uses the
official Docker and LiteSpeed repositories but does not reinstall Git, Codex or
`bubblewrap`. Exact package versions and immutable container digests are kept in
`versions.env`; installation stops instead of silently substituting another
version.

## Deliberately external state

None of the following belongs in Git:

- `/opt/calagopus-panel/.env`;
- PostgreSQL, Valkey, Panel data or logs;
- administrator, database or WebAdmin passwords;
- join tokens, node tokens or other credentials;
- TLS certificates and private keys;
- `/root/workspace/SSL.zip`.

The deployer requires `/root/workspace/SSL.zip` as an external input. It must
contain `fullchain.pem` and its matching `private-key.pem`. The installer checks
the public-key match before placing them at:

```text
/usr/local/lsws/conf/cert/dev-atrioxgame-panel.atrioxhost.com/fullchain.pem
/usr/local/lsws/conf/cert/dev-atrioxgame-panel.atrioxhost.com/private-key.pem
```

`install-panel.sh` generates strong random values for `APP_ENCRYPTION_KEY`,
`POSTGRES_PASSWORD` and the local WebAdmin password. They are stored only in the
root-readable runtime `.env`; the WebAdmin password is also converted to the
OpenLiteSpeed password hash required by WebAdmin.

The local self-signed WebAdmin certificate generated by the OpenLiteSpeed
package is intentionally retained for the SSH-tunnel-only interface. It is not
copied into this repository and is never used for the Panel origin.

## Network and routing invariants

- Panel backend publication: `127.0.0.1:8000:8000` only.
- WebAdmin: `127.0.0.1:7080` only.
- Bunny origin: OpenLiteSpeed `PanelHTTPSv6` on `[ANY]:443` only.
- Bunny hostname: `dev-atrioxgame-panel.atrioxhost.com`.
- Docker IPv4: `172.30.0.0/24`, gateway `172.30.0.1`.
- Docker IPv6: `fd6d:3f4b:7e9c::/64`, gateway `fd6d:3f4b:7e9c::1`.
- NAT66: `fd6d:3f4b:7e9c::/64` through `ens18`, SNAT to
  `2a0c:b641:620::6`.
- The central router firewall and Bunny configuration remain external and are
  never managed by these scripts.

## Fresh prepared VM procedure

Read the complete specification before running anything. The scripts are
intentionally split so package installation and deployment remain reviewable.

```bash
cd /root/workspace/calagopus-panel/deploy/atrioxhosting/panel
./install-prerequisites.sh
./install-panel.sh
./verify-panel.sh
```

`install-panel.sh` refuses to overwrite an existing `/opt/calagopus-panel`
deployment. It pulls the official images once, verifies that the Panel image is
the recorded 1.2.1 image and then starts the standalone stack. It does not run
OOBE and never starts Wings.

Before offering OOBE, run the destructive-in-containers but data-preserving
persistence verification separately:

```bash
./verify-persistence.sh
```

That script first validates every required bind mount, never uses `down -v`,
never removes a Docker volume, and removes only its own temporary database test
table afterward.

After Bunny reaches the IPv6 HTTPS origin and OOBE is completed manually, run
`verify-panel.sh` again. Do not proceed to Wings without Menno's explicit
approval and new Panel-generated join data for that node.

## Validated image

The rebuild used the following Panel image:

```text
ghcr.io/calagopus/panel:latest
ghcr.io/calagopus/panel@sha256:02331d02772a01fb79fc8e95b6b35b96abb079a623b47746b0361d174d6cc0eb
Calagopus Panel 1.2.1
```

The Compose file retains the specification-mandated `:latest` tag. The
installer stops if the Panel, PostgreSQL or Valkey tags do not resolve to the
digests recorded in `versions.env`, or if the Panel does not report the recorded
version. It does not silently deploy another release.
